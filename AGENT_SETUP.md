# AGENT_SETUP.md

**Версия:** 0.1  
**Статус:** Рабочая спецификация  
**Среда:** Ubuntu Linux  
**Агент:** OpenCode (основной вариант, но без жёсткой привязки к конкретному инструменту)

## 1. Цель

Создать локальную систему на базе LLM-агента для поиска и исследования коммерческих возможностей продуктовой студии.

На первом этапе агент выполняет только исследовательскую работу и подготовку отчётов.

Система не должна преждевременно превращаться в сложную платформу или автономную бизнес-инфраструктуру.

## 2. Принятые решения

| Параметр | Решение |
|---|---|
| Основная машина | Локальный Ubuntu |
| Основной агент | OpenCode |
| Запуск | Вручную по команде |
| Основной режим | Исследования и отчёты |
| Хранение данных | Локальные Markdown/YAML |
| Автоматическое обновление реестра | Не требуется на первом этапе |
| Автоматическое проведение экспериментов | Не требуется |
| Публикации и коммуникация | Только после ручного одобрения |
| Удалённый браузер | Не требуется на первом этапе |

## 3. Архитектура

Первоначальная архитектура должна быть минимальной.

```text
Ubuntu
  |
  +-- OpenCode
  |     |
  |     +-- AGENTS.md
  |     +-- Skills
  |     +-- Research workflow
  |     |
  |     +-- Web search / Browser
  |     +-- Local file access
  |
  +-- Business workspace
        |
        +-- Strategy documents
        +-- Research instructions
        +-- Opportunity registry
        +-- Observations
        +-- Research reports
        +-- Validation proposals
```

LLM-агент отвечает за анализ, поиск информации, формирование гипотез и подготовку документов.

Пользователь отвечает за принятие решений и любые действия с финансовыми или репутационными последствиями.

## 5. Режим работы

Агент запускается вручную из каталога проекта.

Пользователь задаёт конкретную задачу, например:

- Найди новые возможности для небольших B2B-инструментов.
- Исследуй проблемы продавцов на российских маркетплейсах.
- Найди перспективные ниши среди Telegram-сервисов.
- Изучи отзывы пользователей конкретного конкурента.
- Оцени эту продуктовую гипотезу.
- Найди небольшие проекты для приобретения.

Агент должен уточнять задачу только тогда, когда без этого невозможно провести качественное исследование.

## 6. Ограничения автономности

На первом этапе агент может:

- искать публичную информацию;
- анализировать сайты и обсуждения;
- изучать конкурентов;
- собирать доказательства;
- формировать гипотезы;
- рассчитывать экономику;
- готовить отчёты;
- предлагать эксперименты;
- готовить проекты документов.

На первом этапе агент не должен самостоятельно:

- менять основной реестр возможностей;
- менять стратегические документы;
- публиковать материалы;
- отправлять сообщения;
- регистрировать аккаунты;
- оплачивать услуги;
- запускать рекламные кампании;
- проводить эксперименты;
- покупать проекты;
- принимать решения о разработке.

Если для исследования нужно создать новый файл, агент может подготовить его как отдельный отчёт или черновик. Изменения в основных документах и реестре должны быть представлены пользователю для проверки.

## 7. Работа с браузером и поиском

На первом этапе использовать доступные возможности поиска и браузера в среде агента.

Требования:

- доступ к публичным источникам;
- возможность открывать страницы;
- возможность изучать несколько источников;
- сохранение ссылок;
- фиксация даты исследования;
- возможность проверять актуальность информации.

Не строить собственную браузерную инфраструктуру до появления реальной необходимости.

Если существующих возможностей OpenCode окажется недостаточно, отдельно оценить:
- MCP-инструменты;
- браузерную автоматизацию;
- удалённый Chromium;
- Google Cloud browser rendering service.

## 8. Формат результатов

Каждая исследовательская задача должна завершаться отчётом.

Отчёт должен содержать:

1. Цель исследования.
2. Метод исследования.
3. Найденные наблюдения.
4. Источники.
5. Продуктовые гипотезы.
6. Конкурентов.
7. Возможности монетизации.
8. Первичную экономическую оценку.
9. Риски.
10. Рекомендации.
11. Следующие действия.

Агент обязан отделять подтверждённые факты от предположений.

## 9. Эволюция системы

Архитектура должна допускать постепенное расширение.

### Этап 1 — Research Assistant

Текущий этап:
- локальный OpenCode;
- ручной запуск;
- исследование;
- отчёты;
- ручное управление документами.

### Этап 2 — Research Operations

Возможное расширение:
- автоматическое ведение реестра;
- дедупликация гипотез;
- сохранение наблюдений;
- история исследований;
- автоматическая подготовка сводок.

### Этап 3 — Validation Assistant

Возможное расширение:
- подготовка посадочных страниц;
- подготовка публикаций;
- создание прототипов;
- сбор заявок;
- анализ результатов экспериментов.

Все действия, связанные с реальными людьми, публикациями и расходами, остаются под контролем владельца.

### Этап 4 — Product Studio Operations

Возможное расширение:
- несколько специализированных агентов;
- периодические исследования;
- мониторинг конкурентов;
- автоматизация отдельных процессов;
- общая аналитика портфеля продуктов;
- интеграция с платежами и продуктовыми метриками.

Переходить к следующим этапам только тогда, когда текущая система доказала свою полезность.

## 10. Критерий готовности первой версии

Первая версия считается готовой, когда можно:

1. Открыть проект в OpenCode.
2. Запустить исследовательскую задачу вручную.
3. Получить реальные источники и проверяемые факты.
4. Получить несколько сформированных гипотез.
5. Получить коммерческую оценку перспективных гипотез.
6. Получить итоговый отчёт в Markdown.
7. Самостоятельно принять решение о дальнейшей работе.

Главный критерий — качество найденных коммерческих возможностей, а не количество файлов, навыков или агентов.
